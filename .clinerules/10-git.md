# Git-правила

- Ветка на каждую задачу от `develop`: `S_NN_название`.
- Не пушить напрямую в `develop`/`main`.
- Коммиты атомарные, сообщение: `<код> <тип> <описание>` (напр. `3.19 doc new ...`).
- Типы: `new`, `fix`, `ref`, `doc`, `infra`, `test`, `upd`.
- **ЗАПРЕТ КОММИТОВ АГЕНТАМ (критично, без исключений):**
  - Агент **никогда** не выполняет `git commit`, `git push`, `gh pr create` — **ни в коде, ни в документации (`ibs-docs`)**.
  - По завершении работы — отчёт строгого формата (см. `20-workflow`) + `git diff`, затем **остановка**.
  - **Коммит делает только руководитель** (или РП по доверенности).
  - **Пуш и PR** — только по явной команде руководителя (механику может поручить агенту).
- Секреты не коммитить — они в `.env` / `docs/09-Служебное/Доступы/` (gitignored).
- Перед PR — прогон тестов и `git merge develop` в своей ветке.
- Документация — в отдельном репо `ibs-docs` (правила: `11-docs.md`), не в этом репо.
