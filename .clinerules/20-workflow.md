# Воркфлоу и статусы

- Конвейер: РП → Аналитик → Лид → Дев+Тест → Ревью(Лид) → Тест → Merge/DevOps. Полная схема: `docs/09-Служебное/Регламенты/Воркфлоу.md`.
- Статусы задачи: `spec → planned → in_progress → review → testing → deploy → done` (+`blocked`, `cancelled`).
- WIP: 1–2 задачи в работе на агента.
- **Docker: по завершении задачи останови свой стек** — `docker compose down` в своём каталоге. RAM на машине ограничена (критично), не держи контейнеры без надобности.
- **КОММИТЫ И PR — СТРОГО ЧЕРЕЗ ПОДТВЕРЖДЕНИЕ РУКОВОДИТЕЛЯ (критичное правило, без исключений):**
  1. Перед КАЖДЫМ коммитом — остановись, пришли отчёт (что сделано) + название коммита, ЖДИ подтверждения руководителя.
  2. Руководитель: принял → коммит делается; не принял → пишет правки, ты исправляешь и повторяешь.
  3. PR (`gh pr create`) — ТОЛЬКО после отмашки руководителя по последнему принятому коммиту.
  Запрещено без подтверждения: коммитить, пушить, создавать PR.
- Смена статуса — в канбане + комментарием в статье задачи (`ДД.ММ.ГГ Кто: текст → кому`).
- Не раздувай задачу: существенная доработка = новая задача. Эскалация: Дев/Тест → Лид → РП → Руководитель.
