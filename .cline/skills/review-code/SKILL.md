# Review-code

## Порядок
1. Подтяни `develop`; определи ветку/PR для ревью.
2. Прочитай диф (`gh pr diff <N>` / код ветки).
3. **Проверь тесты**: посмотри CI-статус PR (зелёный/красный); если CI нет — запусти сам (`docker compose run --rm … php vendor/bin/phpunit`). НЕ доверяй заявленному покрытию.
4. **Security-чек-лист**: JWT/RBAC, IDOR (чужие данные недоступны), XSS, секреты не в git, валидация ввода.
5. **Разделяй** «системный пробел» (существует и вне этой задачи) от «пробела задачи».
6. **Вердикт явный**: готово к мержу / на доработку + список блокеров (по приоритету).

## Куда писать
- Замечания по коду → комментарии в **PR** (inline/суммарно).
- В задачу → **короткий статус**: вердикт + ссылка «замечания в PR #N» (+ краткий security-чек-лист). Не дублируй подробности в задачу.

## Чек-лист
- [ ] Тесты проверены (CI-статус или локальный запуск); в PR заполнена секция «Тесты» (phpunit + phpstan + npm test:unit) — иначе вернуть деву
- [ ] Security-чек-лист пройден
- [ ] Блокеры отделены от рекомендаций
- [ ] Замечания в PR; в задаче — короткий статус
- [ ] Вердикт явный
