# Status-briefing (оперативный обзор / диспетчер)

Снимает переключение контекста руководителя: собрать картину по команде, актуализировать статусы и дать консультацию «что делать дальше».

## Шаги

1. **Git-состояние (и закоммиченное, и незакоммиченное):**
   - 7 клонов **docs** (`ibs-*/docs`): `git status -s` + `git diff --stat` — правки статей = отчёты агентов, которые ещё не закоммичены.
   - 7 клонов **кода** (`ibs-*`): текущая ветка + `git status -s` (незакоммиченный код).
   - клон РП `ibs-docs`: `git pull origin main` + `git status -s`.
2. **Прочитать:** `09-Служебное/Оперативная сводка.md` + `03-Задачи/Канбан.md` + `03-Задачи/Планы спринтов/Текущий спринт.md`.
3. **Сверить отчёты агентов:** прочитать «Комментарии» в статьях задач, **включая незакоммиченные файлы** в рабочих копиях агентов (агент пишет отчёт, но не закоммичено → ждёт ревью/коммита руководителя).
4. **Обновить:**
   - Канбан — передвинуть карточки (двигает только РП).
   - Оперативную сводку — статусы агентов + «Мои действия» P1/P2; явно пометить: «агент отчитался, файл не закоммичен → нужно ревью + коммит».
5. **Консультация:** что делать руководителю по приоритету: где блокеры (P1), где ждут **ревью + коммита** незакоммиченные отчёты, кого подтолкнуть, какие пуши ждут отмашки.

## Правила

- Статусы в Канбане двигает только РП.
- Отчёты агентов могут быть **незакоммиченными** — это нормальный этап «отчитался → жду ревью/коммита руководителя».
- Если данных мало (агент не отчитался) — сказать явно, не додумывать.
