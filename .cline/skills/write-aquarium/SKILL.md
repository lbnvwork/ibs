# Write-aquarium

«Аквариум» — это путеводитель по коду фичи. Читатель (руководитель/лид) проходит по сценарию, как в дебаггере: видит движение данных, содержимое переменных и логику переходов. Это НЕ карта вызовов «функция → функция», а разбор «что происходит и почему».

## Формат

### 1. Идея (1 абзац в начале всего Аквариума)
Что делает фича и какими паттернами/технологиями. Без кода, по-русски.

### 2. Сценарии — один сценарий = один проход по коду
Для каждого сценария:
- **Заголовок** — что за сценарий (позитив/негатив).
- **Идея** (1 строка) — что происходит по-русски.
- **По шагам** — нумерованные шаги.
- **Выход** — что получилось (запись в БД, HTTP, исключение).

### 3. Шаг — как в дебаггере
Каждый шаг содержит:
1. **Вызов** функции/метода с фактическими аргументами.
2. **Переменные** — что лежит в ключевых переменных на входе/выходе (например `$address = '42342534'`).
3. **Русское объяснение** — что делает этот шаг, без англ. жаргона.
4. **Паттерн/решение** (если есть) — почему сделано именно так.

## Требования
- **Движение данных видно**: прослеживается, как значение трансформируется от входа к выходу (например `patientId=42 → chat_id → тело POST → notification_logs`).
- **Переменные конкретные**: не «какое-то значение», а `'42342534'`, `42`, `'Доза 5 мг'`.
- **Русский язык** для объяснений; англ. — только имена классов/методов/полей БД.
- Один сценарий — до 10–15 шагов; длиннее — разбей на под-шаги.

## Пример (задача 3.1, сценарий IMMEDIATE-отправки в MAX)

### Сценарий 1. IMMEDIATE-отправка уведомления в MAX (позитив)

**Идея:** врач шлёт уведомление пациенту 42 через MAX. Система находит chat_id пациента, подставляет текст и делает HTTP-запрос в MAX, затем пишет результат в лог.

**По шагам:**

1. **`NotificationService::send(new Recipient(patientId: 42), new NotificationMessage(body: 'Доза 5 мг'), ['max'], IMMEDIATE)`**
   Входим в `send()`. Переменные: `$recipient->patientId = 42`, `$message->body = 'Доза 5 мг'`, `$channels = ['max']`.

2. **`deliver(rethrow: true)` → `ChannelRegistry::get('max')`**
   Достаём зарегистрированный канал. `$channel = MaxChannel`. *Паттерн: реестр каналов — новый канал добавляется регистрацией, без правки кода доставки.*

3. **`MaxChannel::isAvailable()`**
   Проверяет, заданы ли `MAX_API_URL` и `MAX_BOT_TOKEN` (из `.env`). → `true`.

4. **`PatientContactResolver::get(42, 'max')`**
   SQL по уникальному индексу `(patient_id, channel_type)` → `$address = '42342534'` (это chat_id пациента). *Паттерн: резолвер отделяет «кто» (Recipient) от «куда» (адрес) — новый канал добавляется без правки Patient/Recipient.*

5. **`TemplateResolver::resolve('Доза 5 мг', …)`**
   Подстановка `%key%` → `'Доза 5 мг (подтвердите)'`.

6. **`MaxChannel::send($recipient, '42342534', 'Доза 5 мг (подтвердите)')`**
   HTTP `POST https://max.ru/messages?chat_id=42342534`, заголовок `Authorization: Bearer <token>`, тело `{"text":"Доза 5 мг (подтвердите)"}`.

7. **`log(...)`**
   Запись в `notification_logs`: `status='sent'`, `recipient_address='42342534'`, `external_id`.

**Выход:** сообщение доставлено; в `notification_logs` — `status='sent'`.

## Чек-лист
- [ ] «Идея» есть в начале.
- [ ] Каждый сценарий: Вход → шаги → Выход.
- [ ] В шагах — фактические значения переменных.
- [ ] Русское объяснение каждого шага.
- [ ] Паттерн/решение встроены (где применимо).
- [ ] Движение данных прослеживается от входа к выходу.
