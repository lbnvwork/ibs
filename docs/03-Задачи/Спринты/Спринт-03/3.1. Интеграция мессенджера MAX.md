## Реализация

### План разработки

##### 2. Сущность `PatientChannelIdentity`

**Модуль:** `Ibs\Context\Communication\Entity`

**Таблица:** `patient_channel_identities`

**Поля:**

- `id` — первичный ключ (IDENTITY).
    
- `patientId` — `int`, NOT NULL (внешняя ссылка на пациента, но без FK в БД, чтобы не создавать жёсткую зависимость между контекстами).
    
- `channelType` — `string(32)`, NOT NULL (`sms`, `email`, `push`, `max`).
    
- `value` — `string(255)`, NOT NULL (телефон/email/push-токен/chat_id).
    
- `createdAt`, `updatedAt` — `datetime` (по желанию, но удобно).
    

**Индексы:**

- Уникальный `(patient_id, channel_type)` — один контакт на канал для пациента.
    

**Валидация:**

- `Assert\NotBlank` на `patientId`, `channelType`, `value`.
    
- `Assert\Length(max=255)` на `value`.
    
- `Assert\Regex('/^[^\s]+$/')` на `value` (без пробелов), особенно для `max` и `push`.
    

**Методы:** геттеры/сеттеры, конструктор без обязательных параметров (пустая сущность) или с обязательными, но при API-создании лучше пустой.

- `#[ApiResource]` на `PatientChannelIdentity`.

- API может быть использован фронтендом для отображения и редактирования контактов (особенно MAX chat_id) в карточке пациента.
    

##### 5. Сервис `PatientContactResolver`

**Модуль:** Communication\Service

- Метод `get(int $patientId, string $channelType): ?string`.
    
- Ищет `PatientChannelIdentity` по `patientId` и `channelType`, возвращает `value` или `null`.
    
- Используется `NotificationService` для получения адреса перед отправкой.
    

**Почему это важно:**  
`NotificationService` больше не обращается к `Recipient->phone/email/maxUserId`, а спрашивает резолвер. Это позволяет добавлять новые каналы без изменения `Patient` и `Recipient`.

##### 6. Обновление `ChannelInterface`

##### 6.1. Новая сигнатура `send()`

php

public function send(
    Recipient $recipient,
    string $address,
    NotificationMessage $message
): SendResult;

- `$recipient` — только для `patientId`/`treatmentId` (не содержит адресов).
    
- `$address` — конкретный адрес, полученный из `PatientContactResolver`.
    
- `$message` — как раньше.
    

##### 6.2. Обновить `Recipient`

Убрать поля `phone`, `email`, `pushToken`, `maxUserId` и метод `addressFor`. Оставить:

php

public function __construct(
    public readonly ?int $patientId = null,
    public readonly ?int $treatmentId = null,
) {}

Это сильно упрощает модель и убирает дублирование контактов.

##### 6.3. Обновить `FakeChannel`

- В тестах проверять, что `address` передан корректно.
    

##### 6.4. Обновить `MaxChannel`

- Принимает `$address` как `chat_id`.
    
- Больше **не** обращается к `$recipient->maxUserId`.
    
- Остальная логика (HTTP-запрос, проверка длины, разбор ответа) без изменений.
    

##### 7. Обновление `NotificationService`

##### 7.1. Резолв адреса перед отправкой

В `deliver()` для каждого канала:

1. `$address = $this->contactResolver->get($recipient->patientId, $channelType);`
    
2. Если `$address === null`:
    
    - Логировать `failed` с ошибкой `Address not configured for channel ...`.
        
    - Для `IMMEDIATE` пробрасывать `NotificationDeliveryException`.
        
    - Для `ROUTINE` продолжать со следующим каналом.
        
3. Если адрес есть — передавать его в `sendWithRetries()`.
    

##### 7.2. Ретраи

- Логика `sendWithRetries` остаётся, но теперь `attemptSend()` вызывает `$channel->send($recipient, $address, $resolvedMessage)`.
    

##### 7.3. Логирование

- В `NotificationLog` сохраняем `recipientAddress = $address`.
    
- Поле `externalId` — из `SendResult`.
    

##### 8. Конфигурация `MaxChannel`

- В `services.yaml` зарегистрировать `MaxChannel` с явными аргументами.
    
- Убрать автопривязку строковых аргументов (иначе `autowire` упадёт).
    

##### 9. Тестирование

##### 9.1. Unit `PatientContactResolver`

- Возвращает адрес по patientId и channelType.
    
- `null`, если записи нет.
    
- Кэширование (опционально) — не обязано.
    

##### 9.2. Unit `MaxChannel` (новая сигнатура)

- Успешная отправка: проверка URL, заголовков, тела и `chat_id` из `$address`.
    
- `5xx` → `retryable=true`.
    
- `4xx` → `retryable=false`.
    
- Текст > 4000 → `InvalidArgumentException` до HTTP-запроса.
    
- Пустой `address` → `failure`.
    
- `isAvailable()`.
    

##### 9.3. Unit `NotificationService`

- Резолвер возвращает адрес → канал вызван с этим адресом.
    
- Резолвер возвращает `null` → `failed`, канал **не вызывается**.
    
- Ретраи временных ошибок (первичная + до трёх повторов).
    
- Критические ошибки без повторов.
    
- Асинхронный ROUTINE через Messenger.
    
- Обработчик конверта.
    

##### 9.4. Integration `PatientChannelIdentity`

- Сохранение и получение контакта через EntityManager.
    
- API тест: создание/обновление контакта через API Platform.
    

##### 9.5. Обновить существующие тесты

- Все тесты, где создаётся `Recipient`, `FakeChannel`, `NotificationService`, должны быть адаптированы к новой сигнатуре и отсутствию адресов в `Recipient`.
    

##### 10. Финальные проверки

- Frontend-тесты зелёные (фронтенд не затрагивается, но проверка не помешает).
