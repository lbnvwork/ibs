# 3.24. Изоляция docker-compose стеков агентов

## Основание
В `docker-compose.yml` захардкожены `container_name` (`ibs-php`, `ibs-db`, `ibs-node`, `ibs-nginx`, `ibs-messenger-worker`; из 3.20 — `ibs-e2e`) и порт nginx (`8081:80`). При параллельном запуске стеков агентов (5 dev-стеков) имена контейнеров и порты конфликтуют. Частично параметризовано в `docker-compose.override.yml` (порты db/node через `.env`). Отдельно — VPS (прод, `ssh root@217.199.219.46`): там уже есть разделение docker-compose, его нельзя сломать.

## Навыки (Skills)
`git-workflow`, `run-tests`, `write-instruction`

## Задача
1. Убрать `container_name` из всех сервисов `docker-compose.yml` (Docker авто-имя `${COMPOSE_PROJECT_NAME}-<service>`).
2. Вынести порт nginx в `.env` (`APP_PORT`), как уже сделано для `DB_PORT`/`FRONTEND_PORT` в override.
3. Проверить параллельный запуск 2+ стеков (разные `COMPOSE_PROJECT_NAME`) без конфликтов контейнеров и портов.
4. Свериться с VPS (прод): изучить текущее разделение docker-compose там, убедиться, что правки локали не ломают прод; зафиксировать разницу локали/прода в инструкции.

## Критерии приёмки
- [ ] В `docker-compose.yml` нет `container_name`
- [ ] Порт nginx берётся из `.env` (`APP_PORT`)
- [ ] Два стека с разными `COMPOSE_PROJECT_NAME` поднимаются параллельно
- [ ] Прод (VPS) не затронут; разница локали и прода зафиксирована

## Результат
Стеки агентов изолированы, параллельный запуск без конфликтов.
