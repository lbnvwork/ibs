# 3.16. Структура хранилища docs и миграция канбана

## Основание
По итогам мозгового штурма решили упорядочить хранилище под 4 аудитории читателей (куратор, аналитик, разработчик, тестировщик) + спринтовый архив задач.

## Цель
Создать целевую структуру папок `docs/` и перенести текущие файлы без потери контента и ссылок.

## Задача (шаги)
1. Создать папки: `00-Главная`, `01-Куратор/` (Отчёты, Встречи, Дайджест-переписки), `02-Аналитика/` (Бизнес-логика, Глоссарий, FUNC-матрица, Инструкции), `03-Задачи/` (Backlog, Канбан, Спринты, _Шаблоны), `04-Разработка/` (Архитектура, БД, Модули, ADR, Инструкции), `05-Тестирование/` (Сценарии-E2E, Покрытие, Баги, Инструкции), `06-DevOps/`, `09-Служебное/` (Регламенты, Доступы, Ссылки).
2. Создать `00-Главная.md` — карта (MOC) с навигацией по аудиториям.
3. Перенести `Канбан проекты.md` → `03-Задачи/Канбан.md`.
4. Задачи из `Канбан задачи/`: активные остаются в канбане (ссылки), готовые/отменённые — в `03-Задачи/Спринты/Спринт-N/` по номерам.
5. Разместить текущие документы в новой структуре:
   - `План проекта.md` → `02-Аналитика/FUNC-матрица.md`
   - `Bounded context модули.md` → `02-Аналитика/`
   - `backend-testing-*`, `frontend-testing-*`, `max-integration-testing.md`, `registration-howto.md` → `05-Тестирование/Инструкции/`
   - `Команды.md`, `Ссылки.md`, `Выполненные работы.md` → `09-Служебное/`
   - `Доступы/` → `09-Служебное/` (остаётся gitignored)
   - `Файлы/` (docx ТЗ и справочники) → `01-Куратор/Файлы/`
   - `registration_4_7/` → `01-Куратор/Регистрация/`
6. Проверить, что `[[ссылки]]` в канбане не побились.
7. Секреты остаются в `09-Служебное/Доступы/` (gitignored).

## Критерии приёмки
- [ ] Все текущие файлы перенесены, ничего не потеряно
- [ ] Канбан открывается, активные задачи на месте
- [ ] Готовые задачи разложены по спринтам
- [ ] Ключевые ссылки работают

## Результат
Новая структура + актуальный канбан + карта в `00-Главная.md`.
