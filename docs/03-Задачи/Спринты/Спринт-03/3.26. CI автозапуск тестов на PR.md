# 3.26. CI: автозапуск тестов на PR

## Основание
Ревьюер не должен гонять тесты вручную и доверять «на слово». Нужен GitHub Actions: на каждый PR — phpunit + phpstan + doctrine:schema:validate + composer audit + фронт (vitest + build). Статус-чек в PR — ревьюер только смотрит.

## Навыки (Skills)
`git-workflow`, `run-tests`, `write-instruction`

## Задача
1. Workflow `.github/workflows/ci.yml`:
   - backend (php 8.x + postgres service): `composer install` → `doctrine:migrations:migrate` + `doctrine:schema:validate` → `phpunit` → `phpstan analyse` → `composer validate` (+ `composer audit`).
   - frontend (node 20): `npm ci` → `vitest` → `npm run build`.
2. Тесты с MAX-заглушками (`MAX_API_URL=test`, `MAX_BOT_TOKEN=test`, `MAX_WEBHOOK_SECRET=test` — уже в `api/.env.test`).
3. Проверить, что на PR появляется статус-чек (зелёный/красный).

## Критерии приёмки
- [ ] PR получает статус-чек (phpunit / phpstan / schema / frontend)
- [ ] Падение любого шага → красный чек
- [ ] Инструкция (при необходимости) в `06-DevOps/Инструкции/`

## Результат
Автопроверка на PR; ревьюер не гоняет тесты руками, только смотрит статус.
