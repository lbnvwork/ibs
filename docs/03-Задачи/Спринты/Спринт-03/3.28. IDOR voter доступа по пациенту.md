# 3.28. IDOR: voter доступа по пациенту (системный)

## Основание
Ревью 3.1 выявило системный IDOR: ресурсы без `security:` (`Patient`, `PatientChannelIdentity`, `MaxDeepLinkController`) — любой аутентифицированный читает/пишет данные чужих пациентов. Пробел сквозной, не только 3.1. Вынесено из 3.1 отдельной задачей с фиксацией риска (ревьюер допустил этот вариант).

## Задача
1. Voter доступа по пациенту: цепочка `User → UserForHospital/MedicalPersonnel → Hospital → Patient.hospital`.
2. Применить `security:` к `Patient`, `PatientChannelIdentity`, `MaxDeepLinkController`.
3. Тесты: 401 без JWT; 403/404 на чужого пациента.

## Критерии приёмки
- [ ] Врач видит только своих пациентов (своя больница)
- [ ] Чужие контакты/диплинки недоступны (403/404)
- [ ] Тесты на IDOR зелёные

## Результат
Закрыт системный IDOR; доступ ограничен по больнице/пациенту.
