### Описание

**Цель:**  
Изменить представление таблицы истории болезни (`MedicalTable`) — убрать раздельные колонки «МНО», «Анализ №1», «Анализ №2», «ЧСС», «АД» и заменить их одной колонкой «Показатели», в которой динамически формируется строка в том же формате, что и в дашборде (МНО + Hb + ЧСС + АД + SpO₂ + Вес). Данные за каждый день группируются в одну строку: для МНО берётся значение из `test_history`, для витальных показателей — последние значения из `patient_vitals` за этот день. Назначения остаются отдельными строками.

**Исходное состояние:**

- Таблица `MedicalTable` в карточке пациента (`PatientHistory`) показывает анализы (`test_history`) и назначения (`appointments`) отдельными строками.
    
- Колонки «МНО», «Анализ №1», «Анализ №2», «ЧСС», «АД» выводили каждое поле в своей ячейке.
    
- Витальные показатели не отображались (до задачи 2.22).
    
- Дашборд (задача 2.23) уже умеет показывать сводную строку показателей из `patient_vitals_latest`.
    

**Требования:**

1. **Бэкенд: подготовка данных для таблицы истории**
    
    - В эндпоинте, отдающем данные для `PatientHistory` (или в `loadPatientData`), добавить загрузку всех записей `patient_vitals` для данного лечения, аналогично тому, как загружаются `test_history` и `appointments`.
        
    - На фронтенд должны передаваться как минимум: `record_dt`, `hb`, `heart_rate`, `systolic_pressure`, `diastolic_pressure`, `saturation`, `weight`.
        
2. **Фронтенд: реорганизация `medicalData`**
    
    - В `PatientHistory.script.js` изменить метод формирования массива `medicalData`, который используется `MedicalTable`.
        
    - **Группировка по дням:** для каждого календарного дня (дата события) создать одну запись:
        
        - Если есть записи `test_history` на этот день — взять последнюю (по времени), из неё извлечь МНО.
            
        - Из всех записей `patient_vitals` за этот день взять **последнее** значение каждого показателя (hb, heart_rate, systolic_pressure, diastolic_pressure, saturation, weight). Как именно определить «последнее»: упорядочить по `record_dt DESC` и взять первое не-null для каждого показателя.
            
    - **Формат строки показателей** для полученной записи:
        
        - Сформировать строку-сводку в точности как в дашборде:  
            `МНО X.X, Hb Y, ЧСС Z, АД S/D, SpO₂ W%, Вес V кг`
            
        - Если МНО нет — строка начинается со следующего доступного показателя.
            
        - Если нет ни одного показателя — строка не создаётся (такой день пропускается).
            
    - **Назначения** остаются отдельными строками, как и сейчас (в колонке «Показатели» может быть прочерк или пусто, а в колонке «Доза» и «Рекомендации» — свои данные).
        
    - **Удаление старых колонок:** из шаблона `MedicalTable` убрать колонки «МНО», «Анализ №1», «Анализ №2», «ЧСС», «АД», заменив их одной колонкой «Показатели» (или «Сводка»).
        
3. **Визуальное представление**
    
    - Новая колонка имеет такую же ширину, как и прежние (или адаптивную).
        
    - Внешний вид строки показателей полностью идентичен тому, что используется в дашборде (задача 2.23) — жирный МНО, обычный шрифт для остальных.
        
    - Стили можно переиспользовать через общий компонент `IndicatorsCell`.
        
4. **Совместимость с существующими данными**
    
    - Если по какому-то пациенту ещё нет записей в `patient_vitals`, таблица показывает только МНО (как и раньше) в новой колонке «Показатели», без витальных.
        
    - Назначения корректно отображаются без ошибок.
        
    - График МНО (`MnoChart`) продолжает работать, используя только `test_history`.
        

**Ожидаемый результат:**

- В таблице истории болезни вместо пяти отдельных колонок — одна колонка «Показатели» с компактной сводкой всех доступных данных за день.
    
- Для каждого дня, где есть МНО или витальные показатели, формируется одна строка.
    
- Назначения по-прежнему видны отдельными строками.
    
- Интерфейс не перегружен, врач видит полную картину в привычном формате дашборда.

### Ход разработки
#### План реализации задачи 2.28

##### 1. Бэкенд: добавить фильтр по лечению для `PatientVitals`

В сущности `PatientVitals` не хватает `ApiFilter` для поля `treatment`. Нужно добавить:

php

use ApiPlatform\Doctrine\Orm\Filter\SearchFilter;
// ...
#[ApiFilter(SearchFilter::class, properties: ['treatment' => 'exact'])]

Это позволит фронтенду делать запрос `GET /api/patient_vitals?treatment=/api/treatments/{id}` и получать все витальные записи для конкретного лечения.

##### 2. Фронтенд: загрузка витальных показателей в `medicalTableStore`

В методе `fetchMedicalData` нужно параллельно с назначениями и историей тестов загрузить `patient_vitals` через этот же фильтр:

javascript

apiClient.get('/patient_vitals', {
    params: {
        treatment: treatmentIri,
        order: { recordDt: 'asc' },
        itemsPerPage: 1000
    }
})

Полученный массив сохранить и использовать для группировки.

##### 3. Фронтенд: группировка по дням и объединение показателей

- Пройти по всем загруженным `historyItems` (тестам). Для каждого теста определить день (`YYYY-MM-DD`), взять из `historyItem.mno` МНО.
    
- Из массива витальных записей (`vitalsItems`) выбрать все записи за этот же день и с помощью вспомогательной функции `getLatestVitalsForDay` извлечь последние не‑null значения каждого показателя (hb, heartRate, systolicPressure, diastolicPressure, saturation, weight).
    
- Сформировать объект строки таблицы, содержащий:
    
    - `type: 'test'`
        
    - `date` (для графика)
        
    - `displayDate` (форматированная дата)
        
    - `mno` (из теста)
        
    - `hb, heartRate, systolicPressure, diastolicPressure, saturation, weight` (из витальных)
        
    - `currentDose`, `prescribedDose`, `recommendations`, `comment` (из теста и связанного назначения)
        
- После обработки всех тестов проверить, остались ли дни, для которых были только витальные показатели (без тестов). Для каждого такого дня, если есть хотя бы одно не‑null значение, создать строку с `type: 'vitals_only'`, `mno: null` и заполненными витальными полями.
    
- Назначения, не привязанные ни к каким тестам или витальным, добавляются отдельными строками с `type: 'appointment'` и всеми витальными полями равными `null`.
    
- Отсортировать все строки по дате по убыванию.
    

##### 4. Фронтенд: перенос `buildIndicators` в общий модуль

Переместить файл `vitalsHelpers.js` из `physicianDashboard/utils` в `shared/utils/vitalsHelpers.js`.  
Добавить функцию-обёртку `buildIndicatorsFromRow(row)`, которая внутри вызывает существующую `buildIndicators` с параметрами:

javascript

const testHistory = row.mno != null ? { mno: row.mno } : null;
const vitals = {
    hb: row.hb,
    heartRate: row.heartRate,
    systolicPressure: row.systolicPressure,
    diastolicPressure: row.diastolicPressure,
    saturation: row.saturation,
    weight: row.weight
};
return buildIndicators(testHistory, vitals);

Обновить импорты в компонентах дашборда (`PatientMonitoring`, `PatientWorkList`), чтобы они использовали новый путь.

Чтобы они заработали в `MedicalTable`, нужно либо скопировать соответствующие стили в `MedicalTable.style.css`, либо вынести их в общий CSS-файл и импортировать в `main.js`.
