### Описание

**Цель:**  
В таблице истории болезни для каждой строки, соответствующей **назначению** (appointment), отображать текст SMS, которое было отправлено пациенту именно по этому назначению. Для записей анализов и витальных показателей колонка «Рекомендации» остаётся пустой.

**Исходное состояние:**

- Таблица `appointments` содержит поле `sms_id` (FK → `sms_out.id`).
    
- В `sms_out` хранится текст сообщения (`text`), дата создания и привязка к лечению.
    
- При загрузке истории болезни API не возвращает текст связанного SMS для назначений.
    
- Индекс по полю `sms_id` в таблице `appointments` отсутствует.
    

**Требования:**

1. **Индекс для оптимизации**
    
    - Создать индекс `idx_appointments_sms_id` на поле `sms_id` таблицы `appointments`.
        
    - Индекс ускорит JOIN при выборке назначений с их SMS, особенно при росте количества записей.
        
2. **Бэкенд: расширение данных о назначениях**
    
    - При формировании списка событий истории болезни для каждого назначения с ненулевым `sms_id` загружать связанное SMS из `sms_out` (используя индекс) и добавлять поле `smsText` в ответ API.
        
    - Если `sms_id = NULL` или SMS не найдено, `smsText` устанавливать в `null`.
        
    - Для анализов (`test_history`) и витальных показателей (`patient_vitals`) SMS не загружаются.
        
3. **Фронтенд: отображение в таблице**
    
    - В колонке «Рекомендации» для строк назначений выводить `smsText`, если он не `null`. Иначе ячейка пустая.
        
    - Для строк анализов и витальных показателей колонка всегда пустая.
        
4. **Динамическое обновление**
    
    - Данные загружаются при открытии карточки и переключении пациентов, колонка обновляется автоматически.
        

**Ожидаемый результат:**

- Врач видит текст SMS, отправленного по каждому назначению, непосредственно в строке назначения в колонке «Рекомендации».
    
- Назначения без SMS и другие события (анализы, витальные) не содержат текста.
    
- Производительность JOIN’а обеспечена индексом.

**Тест-кейс (2.30)**

|№|Действие|Ожидаемый результат|
|---|---|---|
|1|Открыть карточку пациента, у которого есть назначения с отправленными SMS.|В строках этих назначений колонка «Рекомендации» содержит соответствующий текст из `sms_out.text`.|
|2|Проверить назначение без SMS (sms_id = NULL).|Ячейка пуста.|
|3|Убедиться, что строки анализов и витальных показателей не содержат текста в этой колонке.|Ячейки пусты.|
|4|Переключиться на другого пациента с назначениями и SMS.|Данные обновлены, текст SMS соответствует новому пациенту.|

**Примечание:**  
Индекс `idx_appointments_sms_id` необходимо добавить через миграцию перед реализацией бэкенда. Текущий внешний ключ `fk_6a41727abd5c7e60` уже гарантирует целостность, но не создаёт индекс автоматически (в PostgreSQL для FK индекс не создаётся неявно).
