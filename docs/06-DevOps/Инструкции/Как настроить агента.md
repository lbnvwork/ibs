# Как настроить агента (Cline)

## Назначение
Подготовка агента к работе по модели «1 чат = 1 агент»: отдельный каталог и Docker-порты, роль `.clinerules/00-role.md`, общие правила `.clinerules/10..50`, навыки (`.cline/skills/` в git + глобальное зеркало), проверка подхвата в Cline.

## Предусловия
- VS Code + расширение Cline v4.1.11.
- Клон репозитория в отдельный каталог и уникальные порты (см. `.env` каталога и `docs/Команды.md`).
- Навыки приходят из develop (`.cline/skills/`); глобальное зеркало `~/.cline/skills/` — опционально.

## Шаги
1. **Каталог и порты** — у каждого агента свой клон (`ibs-<агент>`) и уникальные порты nginx/PostgreSQL/Vite.
2. **Роль** — создай `.clinerules/00-role.md` с промтом роли из Приложения ниже. Файл в git не попадает (`.gitignore` → `.clinerules/00-role.md`).
3. **Общие правила** — `.clinerules/{10-git,20-workflow,30-tdd,40-security,50-dod}.md` приходят из develop (коммитятся). Меняй их только через PR в develop.
4. **Навыки** — канон в `.cline/skills/<имя>/SKILL.md` (workspace, коммитится в develop) + опционально зеркало `~/.cline/skills/`. Как использовать — раздел «Навыки (Skills)» ниже.
5. **Проверка** — Rules-панель (правила загружены), Skills-меню (навыки видны), новый чат (роль подхвачена).

## Навыки (Skills)

Скиллы — модульные инструкции, которые грузятся **по запросу** (в отличие от правил, которые активны всегда): метаданные (`name`+`description`) — всегда (~100 токенов/скилл), тело `SKILL.md` — при активации (<5k), ресурсы `docs/`/`scripts/` — по надобности.

### Как использовать
- **Авто** — запрос совпал с `description` → Cline сам активирует скилл (`use_skill`).
- **Вручную** — слэш `/имя-скилла` в чате.
- **Из задачи** — в статье задачи секция «Навыки» перечисляет скиллы; агент активирует их явно.
- **Просмотр/вкл-выкл** — иконка весов внизу панели Cline → вкладка **Skills**.

### Где живут
| Тип | Путь | В git |
| --- | --- | --- |
| Workspace (канон) | `.cline/skills/<имя>/SKILL.md` | ✅ коммитим |
| Global (зеркало) | `~/.cline/skills/<имя>/SKILL.md` | ❌ локально |

### Формат
```markdown
---
name: my-skill            # == имя папки
description: Что делает и когда использовать (≤1024 симв.)
---
# My Skill
Инструкции при активации.
```
Опционально: `docs/`, `templates/`, `scripts/` (подключаются из SKILL.md).

### Маппинг агент → скиллы (по умолчанию)
| Скилл | Кто использует |
| --- | --- |
| git-workflow | все |
| write-instruction | все |
| run-tests | лид, dev-may, dev-jun, тестировщик, devops |
| write-adr | лид, аналитик |
| explain-db | лид, dev-may, dev-jun |
| write-e2e-scenario | тестировщик |
| make-postman | тестировщик |

## Примеры
Проверка роли: в новом чате спроси «какая у тебя роль и что ты заполняешь в задаче?» — ответ должен следовать `00-role.md`.
Проверка скилла: в чате набери `/git-workflow` — Cline должен загрузить инструкции скилла.
Создание PR (только после отмашки руководителя): `gh pr create --base develop --head <ветка> --title 'S.NN Название' --body-file <файл>`.

## Чек-лист
- [ ] Каталог и порты уникальны
- [ ] `.clinerules/00-role.md` создан (gitignored)
- [ ] Правила видны в Rules-панели Cline
- [ ] Навыки видны в Skills-меню
- [ ] Навыки версионированы в git (`.cline/skills/`)
- [ ] Роль подхватывается в новом чате

## Приложение 2. Навыки (SKILL.md × 7)

Каждый навык — содержимое `.cline/skills/<имя>/SKILL.md` (workspace, коммитится в develop). Ниже — эталон для восстановления глобального зеркала `~/.cline/skills/`.

### explain-db

```markdown
---
name: explain-db
description: Анализ запросов к БД через EXPLAIN ANALYZE, проверка индексов, устранение N+1.
---

# Explain-db

- Для запросов к БД используй `EXPLAIN ANALYZE`, план фиксируй в секции «Реализация» статьи задачи.
- Проверяй использование индексов; при необходимости добавляй.
- Избегай N+1.
```

### git-workflow

```markdown
---
name: git-workflow
description: Работа с git — ветки, коммиты, пул-реквесты. Использовать при создании ветки, коммите или PR.
---

# Git-workflow

- Ветка на задачу от `develop`: `S_NN_название`.
- Коммит: `<код> <тип> <описание>` (напр. `3.19 doc new ...`).
- По завершении, после отмашки руководителя, создай PR: `gh pr create --base develop --head <ветка> --title 'S.NN Название' --body-file <файл>`. Тело — по шаблону `docs/03-Задачи/_Шаблоны/PR.md`.
- Перед PR: прогон тестов + `git merge develop` в своей ветке.
- Не пушить напрямую в `develop`/`main`.
```
