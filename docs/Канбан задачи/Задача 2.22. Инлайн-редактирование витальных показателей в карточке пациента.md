### Описание

- **Спринт:** 2  
- **Код:** 2.22  
- **Оценка:** 1.5 дня  
- **Функция:** FUNC-017 (Дашборд врача)  
- **Статус:** К выполнению  

**Цель:**  
Добавить в карточку пациента постоянно видимый блок «Витальные показатели», который отображает последние значения Hb, ЧСС, АД, сатурации, веса и позволяет врачу в один клик обновить их, создав новое измерение (без удаления истории). Редактирование выполняется inline, без модального окна.

**Исходное состояние:**  
- Задача 2.21 выполнена: таблицы `patient_vitals` и `patient_vitals_latest` созданы, API `POST /api/patient_vitals` работает, сервис синхронизации кэша обновляет `patient_vitals_latest`.  
- Поле `weight` добавлено задачей 2.25.  
- В карточке пациента (`PatientHistory`) нет блока витальных показателей.  
- API пациента не возвращает последние витальные данные (необходимо добавить).

**Требования:**

1. **Бэкенд: получение последних витальных показателей пациента**
   - Добавить в ресурс `Patient` (или создать отдельный эндпоинт) возможность получить последние витальные показатели из `patient_vitals_latest`.  
   - Предлагаемый вариант: при запросе `GET /api/patients/{id}` добавить в ответ вложенный объект `latestVitals` (или включить в состав объекта пациента через расширение группы сериализации).  
   - Структура `latestVitals`:
     ```json
     {
       "hb": 120.0,
       "heartRate": 72,
       "systolicPressure": 130,
       "diastolicPressure": 85,
       "saturation": 98,
       "weight": 70.5,
       "lastUpdated": "2026-07-01T10:00:00+03:00"
     }
     ```
   - Если ни одной записи в `patient_vitals` нет, все поля (кроме `lastUpdated`) равны `null`, `lastUpdated` — `null`.  
   - Это изменение необходимо, чтобы фронтенд мог загрузить актуальные показатели при открытии карточки и после сохранения нового измерения.

2. **Фронтенд: блок «Витальные показатели»**
   - Создать компонент `VitalsCard.vue` (в папке `PatientHistory`).  
   - В шаблоне `PatientHistory.template.html` разместить его между блоком персональных данных (`PatientCard`) и блоком «Лечение» (`TreatmentCard`), аналогично `PharmacogeneticsSection`.  
   - Компонент получает последние витальные данные через пропс или из сторов (в зависимости от архитектуры после рефакторинга).

3. **Режим чтения**
   - Всегда отображается, когда редактирование неактивно.  
   - Формат вывода:
     - «Hb: 120 г/л», если значение есть, иначе «Hb: —».
     - «ЧСС: 72 уд/мин».
     - «АД: 130/85 мм рт. ст.» (если оба значения присутствуют), иначе «АД: —».
     - «SpO₂: 98%».
     - «Вес: 70.5 кг».
     - Под ними — дата последнего измерения: «Последнее измерение: 01.07.2026 10:00». Если записей нет — «Нет данных».
   - В правом верхнем углу блока кнопка «Редактировать» (стилизованная как в других блоках).

4. **Режим редактирования**
   - Активируется нажатием «Редактировать» (флаг `editingVitals` в компоненте).
   - Поля становятся редактируемыми:
     - Hb — `<input type="number">`, предзаполнен последним значением (или пусто).
     - ЧСС — аналогично.
     - Систолическое АД.
     - Диастолическое АД.
     - Сатурация.
     - Вес.
     - Дата и время измерения (`recordDt`) — `<input type="datetime-local">`, **по умолчанию текущие дата и время**, но врач может изменить (например, если вносит вчерашние данные).
     - Комментарий — `<textarea>`.
   - Валидация (клиентская):
     - Хотя бы одно числовое поле должно быть заполнено.
     - Для каждого заполненного — проверка диапазона (те же, что в API).
     - При ошибках — сообщение в верхней части блока, кнопка «Сохранить» неактивна или выдаёт предупреждение.
   - Кнопки: «Сохранить» и «Отмена».
   - При нажатии «Отмена» все поля возвращаются к исходным значениям (тем, что были до редактирования), режим редактирования выключается.

5. **Сохранение**
   - При нажатии «Сохранить» отправляется `POST /api/patient_vitals` с телом:
     ```json
     {
       "patient": "/api/patients/{id}",
       "treatment": "/api/treatments/{activeTreatmentId}",
       "recordDt": "2026-07-01T10:00:00+03:00",
       "hb": 120,
       "heartRate": 72,
       "systolicPressure": 130,
       "diastolicPressure": 85,
       "saturation": 98,
       "weight": 70.5,
       "comment": "..."
     }
     ```
   - Поля, оставленные пустыми, не включаются или передаются как `null`.
   - После успешного ответа (201) компонент получает обновлённые `latestVitals` (можно либо перезагрузить пациента через `loadPatientData`, либо напрямую обновить локальный объект, имитируя ответ). Режим редактирования выключается, отображаются новые значения.
   - При ошибке (422) сообщения из ответа показываются в блоке ошибок.

6. **Интеграция с существующей карточкой**
   - `PatientHistory` при загрузке данных пациента должен также подгружать `latestVitals` (если используется отдельный запрос, добавить его в `loadPatientData`).  
   - Блок витальных показателей всегда виден, даже если нет ни одной записи (отображается «Нет данных», кнопка «Редактировать» активна — позволяет внести первое измерение).  
   - Кнопка редактирования не зависит от статуса лечения (можно обновлять витальные показатели, даже если лечение завершено? Лучше уточнить: обычно жизненные показатели могут вноситься всегда, но если лечение завершено, `treatment` можно не передавать. Но для простоты можно разрешить всегда, передавая `treatment: null`, если активного лечения нет.)

**Ожидаемый результат:**
- В карточке пациента всегда виден блок с последними витальными показателями (Hb, ЧСС, АД, SpO₂, вес) и датой последнего измерения.
- По кнопке «Редактировать» блок переходит в режим inline-редактирования с предзаполненными значениями.
- При сохранении создаётся новая запись в `patient_vitals`, кэш обновляется, и блок сразу отображает актуальные данные.
- Валидация работает как на клиенте, так и на сервере.

**Файлы для доработки:**
- **Бэкенд:** расширение API Patient (или новый контроллер), чтобы включить `latestVitals` (если ещё не сделано).  
- **Фронтенд:**  
  - `VitalsCard.vue` (новый компонент).  
  - `PatientHistory.template.html` — вставка компонента.  
  - `PatientHistory.script.js` — добавление загрузки `latestVitals` и методов для сохранения.

**Зависимости:**

### Ход разработки

#### План разработки

##### 1. `2.22_backend_add_patient_vitals_latest_endpoint`

- Уже реализовано: эндпоинт `GET /api/patient_vitals_latest/{patientId}` отдаёт последние показатели из кэша.
    
- Проверить, что ответ содержит все нужные поля (hb, heartRate, systolicPressure, diastolicPressure, saturation, weight, lastUpdated).
    
- Дополнительных действий не требуется, фиксируем коммит.
    

##### 2. `2.22_frontend_add_vitals_api_and_store`

- Создать `frontend/src/api/vitals.js`:
    
    - `getLatest(patientId)` → `GET /patient_vitals_latest/{patientId}`
        
    - `create(data)` → `POST /patient_vitals`
        
- Создать `frontend/src/modules/patientCard/stores/vitalsStore.js`:
    
    - Состояние: `latest`, `loading`, `error`.
        
    - Действия: `fetchLatest(patientId)`, `saveMeasurement(payload)`.
        
- Убедиться, что алиас `@/modules` работает в конфигурации Vite/Webpack.
    

##### 3. `2.22_frontend_add_vitals_card_component`

- Создать папку `frontend/src/modules/patientCard/components/VitalsCard/` (сам модуль `patientCard` появится в структуре).
    
- Внутри:
    
    - `VitalsCard.vue`
        
    - `VitalsCard.script.js` – логика чтения/редактирования/сохранения, использование `useVitalsStore`.
        
    - `VitalsCard.template.html` – вёрстка по макету (режим просмотра и редактирования).
        
    - `VitalsCard.style.css` – минимальные стили, гармонирующие с остальными блоками.
        
- Компонент принимает пропсы `patientId` и `treatmentId`.
    

##### 4. `2.22_frontend_integrate_vitals_card_into_patient_history`

- В `PatientHistory.template.html` добавить `<VitalsCard>` в левую колонку между `PatientCard` и `Pharmacogenetics`.
    
- В `PatientHistory.script.js`:
    
    - Импортировать `VitalsCard` из нового пути.
        
    - Добавить вычисляемое свойство `activeTreatmentId` (из `treatmentStore.treatment['@id']`).
        
    - При загрузке данных пациента также вызывать `vitalsStore.fetchLatest(this.id)` (или разрешить компоненту самому загружать при монтировании).
        
- Проверить, что блок всегда виден, даже если показателей ещё нет (отображается «Нет данных»).
