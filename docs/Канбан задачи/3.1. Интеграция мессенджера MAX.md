#### План разработки

##### 2. Сущность `PatientChannelIdentity`

**Модуль:** `Ibs\Context\Communication\Entity`

**Таблица:** `patient_channel_identities`

**Поля:**

- `id` — первичный ключ (IDENTITY).
    
- `patientId` — `int`, NOT NULL (внешняя ссылка на пациента, но без FK в БД, чтобы не создавать жёсткую зависимость между контекстами).
    
- `channelType` — `string(32)`, NOT NULL (`sms`, `email`, `push`, `max`).
    
- `value` — `string(255)`, NOT NULL (телефон/email/push-токен/chat_id).
    
- `createdAt`, `updatedAt` — `datetime` (по желанию, но удобно).
    

**Индексы:**

- Уникальный `(patient_id, channel_type)` — один контакт на канал для пациента.
    

**Валидация:**

- `Assert\NotBlank` на `patientId`, `channelType`, `value`.
    
- `Assert\Length(max=255)` на `value`.
    
- `Assert\Regex('/^[^\s]+$/')` на `value` (без пробелов), особенно для `max` и `push`.
    

**Методы:** геттеры/сеттеры, конструктор без обязательных параметров (пустая сущность) или с обязательными, но при API-создании лучше пустой.

##### 5. Сервис `PatientContactResolver`

**Модуль:** Communication\Service

- Метод `get(int $patientId, string $channelType): ?string`.
    
- Ищет `PatientChannelIdentity` по `patientId` и `channelType`, возвращает `value` или `null`.
    
- Используется `NotificationService` для получения адреса перед отправкой.
    

**Почему это важно:**  
`NotificationService` больше не обращается к `Recipient->phone/email/maxUserId`, а спрашивает резолвер. Это позволяет добавлять новые каналы без изменения `Patient` и `Recipient`.

##### 9. Тестирование

##### 9.1. Unit `PatientContactResolver`

- Возвращает адрес по patientId и channelType.
    
- `null`, если записи нет.
    
- Кэширование (опционально) — не обязано.
    

##### 9.2. Unit `MaxChannel` (новая сигнатура)

- Успешная отправка: проверка URL, заголовков, тела и `chat_id` из `$address`.
    
- `5xx` → `retryable=true`.
    
- `4xx` → `retryable=false`.
    
- Текст > 4000 → `InvalidArgumentException` до HTTP-запроса.
    
- Пустой `address` → `failure`.
    
- `isAvailable()`.
    

##### 9.3. Unit `NotificationService`

- Резолвер возвращает адрес → канал вызван с этим адресом.
    
- Резолвер возвращает `null` → `failed`, канал **не вызывается**.
    
- Ретраи временных ошибок (первичная + до трёх повторов).
    
- Критические ошибки без повторов.
    
- Асинхронный ROUTINE через Messenger.
    
- Обработчик конверта.
    

##### 9.4. Integration `PatientChannelIdentity`

- Сохранение и получение контакта через EntityManager.
    
- API тест: создание/обновление контакта через API Platform.
