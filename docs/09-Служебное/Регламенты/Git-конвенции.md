# Git-конвенции

## Ветки

- Основная ветка — `develop`. `main` — релизы (без необходимости не трогаем).
- На каждую задачу — feature-ветка от `develop`: `S_NN_название` (напр. `3_16_docs_structure`).

## Коммиты

- Атомарные, с осмысленным сообщением.
- Формат: `<код задачи> <тип> <описание>`, напр. `3.16 doc new Структура хранилища docs`.
- Типы: `new` (фича), `fix`, `ref`, `doc`, `infra`, `test`, `upd` (обновление).

## Пул-реквесты

- По завершении агент **сам создаёт PR** в `develop` (`gh pr create`).
- Заголовок: `S.NN Название задачи`. Описание — по шаблону `03-Задачи/_Шаблоны/PR.md`.
- Ревью и мёрдж — **только руководитель**.
- Перед PR — прогон тестов и `git merge develop` в своей ветке (разрешить конфликты).

## Правила

- Не пушить напрямую в `develop`/`main`.
- Не коммитить секреты (токены, пароли) — они в `.env`/`docs/09-Служебное/Доступы/` (gitignored).
