Конвейер разработки: от постановки задачи до мержа и деплоя. Все участники (включая РП) работают только через задачи.

## Этапы конвейера

1. **Постановка (РП)** — формирует задачу `S.NN` из ТЗ/требований куратора; заполняет «Основание».
2. **Анализ (Аналитик)** — описывает бизнес-логику, пишет постановку-промт и сценарии (позитив/негатив).
3. **Планирование (Лид)** — критически перерабатывает сценарии, дополняет security, пишет план, скелеты TDD-тестов, формирует «Финальную постановку».
4. **Реализация (Дев) + подготовка E2E (Тестировщик)** — параллельно.
5. **Реализация (Дев)** — код до зелёных тестов, `EXPLAIN` для запросов к БД, рефакторинг.
6. **Ревью (Лид)** — ревью кода + «аквариум» (трассировка по сценариям), замечания.
7. **Доработка + тестирование (Дев → Тестировщик)** — правки по ревью, прогон E2E, ручное тестирование, postman-коллекция.
8. **Merge + деплой (Лид/DevOps)** — PR в `develop`, деплой на тестовый, ручная проверка руководителем.

## Схема

```mermaid
sequenceDiagram
    participant РП
    participant Аналитик
    participant Лид
    participant Дев
    participant Тест
    participant DevOps

    РП->>Аналитик: задача S.NN + «Основание»
    Аналитик->>Лид: бизнес-логика, сценарии, постановка
    Лид->>Лид: план + TDD-скелеты + security-сценарии
    Лид->>Дев: «Финальная постановка»
    Лид->>Тест: сценарии для E2E
    Дев->>Дев: реализация до зелёных тестов
    Дев->>Лид: PR + «Реализация» + «Аквариум» (черновик)
    Лид->>Дев: ревью + «Аквариум» (верификация) + замечания
    Дев->>Тест: правки по ревью
    Тест->>Дев: E2E / ручное / postman — результаты
    Дев->>DevOps: merge в develop
    DevOps->>Тест: деплой на тестовый сервер
    Тест->>РП: E2E на тестовом (через интернет)
    РП->>РП: ручная проверка руководителем
```

## Артефакты задачи

- Статья задачи (секции по ролям) — шаблон `03-Задачи/_Шаблоны/Задача.md`.
- PR — шаблон `03-Задачи/_Шаблоны/PR.md`.
- Комментарии — живой журнал в статье задачи (формат: `ДД.ММ.ГГ Кто: текст → кому`).

## Участие человека (Макс)

Макс ведёт непрерывный мониторинг на всех этапах, но **подключается на финализациях**:

1. **Чекпоинт перед каждым коммитом** — агент останавливается, предлагает название коммита и даёт отчёт («что сделано + что дальше»). Макс подтверждает или правит → агент продолжает.
2. **Ревью и мёрдж PR** — только Макс.
3. **Ручная проверка** на тестовом сервере — только Макс.
4. **Финальные решения** — приоритеты, эскалации, изменение требований.

План реализации в задаче — чек-лист подзадач, каждая подзадача соответствует одному коммиту. По завершении подзадачи агент прерывается, Макс ставит чек и даёт команду продолжать.

## Задачи без разработчика

Не все задачи проходят полный конвейер. Задачи РП, Аналитика, Тестировщика, DevOps, не требующие разработчика, идут по упрощённому потоку:

| Тип | Пример | Упрощённый поток |
|---|---|---|
| Doc (РП) | структура хранилища, шаблоны, регламенты | РП → чекпоинты Макса → PR → мёрдж |
| Doc (Аналитик) | описание существующего функционала | Аналитик → чекпоинты → PR → мёрдж |
| Тест-покрытие (Тестировщик) | E2E/unit на существующий функционал | Тестировщик → чекпоинты → PR → мёрдж |
| Infra (DevOps) | gh/PR, CI, деплой, Docker | DevOps → чекпоинты → PR → мёрдж |

Такие задачи не проходят этапы «Сценарии», «Финальная постановка», «Реализация», «Аквариум».
