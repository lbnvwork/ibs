# Эскалация и обратная связь

## Принцип

Обратная связь по ходу задачи — норма. Но она не должна раздувать задачу или зацикливать агентов.

## Правила

1. **Обратная связь, меняющая сценарии/требования** → эскалация к РП (решение принимается оперативно).
2. **Не раздуваем задачу** — существенная новая доработка = новая задача, а не расширение текущей.
3. **Адресат решает** — комментарий с `→ <агент>` означает, что решение принимает адресат; не может решить сам — эскалирует выше.
4. **Ограничение циклов правок** — не более 2 циклов «дев ↔ лид ↔ тестировщик»; дальше — к РП.

## Эскалационная цепочка

`Дев / Тестировщик → Лид → РП → Руководитель`.

## Фиксация

Все решения и эскалации — в «Комментариях» статьи задачи.
